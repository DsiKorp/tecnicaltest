Concepto SOAP REST
Contrato WSDL 1.1 (XML) OpenAPI 3.0 (YAML o JSON)
Genera código wsimport -p <paquete> http://host:8080/q02/wsdl openapi-generator generate -i http://host:8080/q02/openapi.yaml
Payload XML dentro de un sobre SOAP (verboso) JSON (ligero)
Transporte HTTP, pero con su propio sobre y un binding por operación HTTP tal cual: GET, POST, códigos de estado, cabeceras
Ecosistema Heredado: WS-Security, WS-ReliableMessaging, interoperabilidad con stacks antiguos Estándar de facto: Swagger UI, Postman, gateways, client generators
Cuándo elegirlo Contratos muy estables, Integración con software legacy, seguridad WS-* El 90% de las APIs nuevas: payloads ligeros y consumo del contrato con OpenAPI

El punto clave para la entrevista: WSDL y OpenAPI son la misma idea aplicada a dos mundos — contrato primero. La documentación del servicio y la generación de clientes no son un extra: son el mecanismo. SOAP lleva 25 años haciéndolo con WSDL; REST lo ha heredado con OpenAPI.
